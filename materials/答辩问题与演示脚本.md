# 答辩问题与演示安排

## 1至2分钟演示视频

最终视频应录制实际程序窗口；训练检查子集生成的视频不能作为正式模型演示。录制前准备正式`outputs/runs/eca_p2_e100/weights/best.pt`、未参与训练的视频或test-dev图片，先运行推理确认文件可读。若用静态图片连续展示，应在画面中标注“图片检测展示”。

正式权重已在Linux服务器上对两张test-dev图片实际运行推理，输出存于本地`outputs/demo_e100/`（未上传Git仓库）。密集样例得到131个预测，遮挡样例得到364个预测；两份JSON、CSV行数一致，所有框均在原图宽高内。它们是**静态图片检测样例**，不是运行录屏或视频帧。录屏时在**Windows电脑**录下VS Code窗口；下面的Linux命令仅运行检测并保存结果，不会弹出图形窗口，也不会自行开始录屏。

### Windows电脑上的录屏步骤

1. 在VS Code中打开服务器项目，左侧文件树准备好`outputs/demo_e100/dense/`；把终端字号调大，让命令和图片容易看清。开始录屏前关闭弹窗和无关窗口。
2. 在Windows按`Win + Shift + R`，框选包含VS Code终端和编辑区的屏幕区域，点“开始”。若快捷键无效，从开始菜单打开“截图工具”，选“录制”→“新建”→框选区域→“开始”。录屏操作发生在Windows电脑上，Linux服务器不需要UI界面。参考：[微软截图工具说明](https://support.microsoft.com/en-us/windows/apps/use-snipping-tool-to-capture-screenshots)。
3. 录制过程中，在服务器终端运行以下命令。这里使用新目录`outputs/demo_recording/dense`，避免把旧演示文件误当成刚运行的输出：

```bash
cd ~/private/code/zcp/yolo_pedestrian
export CUDA_VISIBLE_DEVICES=GPU-1475e7c4-6dde-5be5-c5fc-e0d787fb252d
/home/lthpc/.conda/envs/zcp_train/bin/python run.py predict \
  --weights outputs/runs/eca_p2_e100/weights/best.pt \
  --source data/prepared/originals/test/9999938_00000_d_0000207.jpg \
  --output outputs/demo_recording/dense --imgsz 960 --conf 0.25
echo "推理退出码：$?"
ls -lh outputs/demo_recording/dense/
cat outputs/demo_recording/dense/inference_info.json
```

4. 退出码为`0`且目录内有`000000_9999938_00000_d_0000207.jpg`、`detections.json`、`detections.csv`和`inference_info.json`时，在VS Code左侧文件树打开标注JPG，再打开JSON/CSV展示坐标与置信度。可把此前的基线图与完整模型图并排展示，但画面须注明“图片检测展示”；这些文件是图片推理结果，不是视频输入产生的视频。
5. 录到约1–2分钟后点击截图工具的“停止”，保存为MP4，例如`materials/演示录屏原片.mp4`。先播放检查画面能否看清、声音是否需要保留，再把原片提供给后期制作。若需要录旁白，可边操作边讲，也可先录无声画面后配音。

如果使用的是没有视频录制功能的截图工具，可用Windows的Xbox游戏栏录制VS Code应用窗口：`Win + Alt + R`开始/停止，MP4保存在“视频/Captures”。参考：[微软Xbox游戏栏说明](https://support.microsoft.com/en-us/accessibility/windows/use-a-screen-reader-to-record-your-screen-with-xbox-game-bar)。

```bash
/home/lthpc/.conda/envs/zcp_train/bin/python run.py predict \
  --weights outputs/runs/eca_p2_e100/weights/best.pt \

```

## 常见答辩问题

1. **为何不直接放大输入？** 放大输入可以保留更多像素，但同时增加全网络计算。P2改变检测尺度，ECA改变通道响应；三者的作用不同。本项目只把推理分辨率作补充分析，四组训练尺寸保持一致。
2. **为何采用YOLOv8n？** 轻量模型适合检验精度与开销的权衡，结构改动易解释。不能据此声称比所有模型更优。
3. **ECA增加多少参数？** 核大小3且无偏置，每个ECA仅3个卷积权重，两个模块合计6个；全局池化和Sigmoid没有可训练参数。计算与访存开销仍需计时。
4. **ECA是不是空间注意力？** 不是。它对全局空间信息池化后计算通道权重；不能把结果称为空间热图。
5. **P2步长为什么是4？** 输入经过两次stride=2卷积，空间尺寸缩小为四分之一。960输入时P2特征为240×240。
6. **为什么同时保留P5？** 深层特征提供语义和上下文，也支持图中较大的目标。P2通过颈部融合获得深层语义。
7. **小目标是否等于距离远？** 不严格等价。目标像素尺寸还受相机焦距、姿态和图像分辨率影响；本系统只检测二维框，不估计真实距离。
8. **为什么将pedestrian和people合并？** 项目检测人体，合并避免将其他姿态的人体当背景；报告需明确该单类口径。
9. **忽略区域为何不能直接删除标注？** 删除GT后仍把预测计为FP会产生错误监督和评价。训练采用遮罩、评估采用单独忽略规则。
10. **IoA和IoU区别是什么？** IoA使用交集除以预测框面积，适合判断预测大部分落入大忽略区域；IoU使用并集面积。
11. **AP_small为何用原图面积？** 用推理尺寸划分会导致同一对象在640与1280评估时跨组，混淆分辨率效果。
12. **四组预训练是否公平？** 都只加载同一个官方骨干，颈部和检测头重新初始化；加载键列表可检查。
13. **最佳权重怎么选？** 每轮验证集忽略区感知mAP50–95最高的权重；测试集不参与。
14. **为何一次运行不能证明稳定提升？** 单种子只能提供该次实验结果，随机性仍存在。课程标准实验不进行三种子重复，应诚实说明限制。
15. **FPS包括读取和显示吗？** 项目分别测模型前向和预处理+NMS；磁盘读取、画框、编码被明确排除。不能将它们称为整个视频程序吞吐。
16. **哪些结果仍待完成？** 四组各100轮、test-dev评估和正式速度已经完成。仍需1–2分钟真实运行录屏、DOCX/PPTX排版与逐页检查，以及学生个人信息和实际分工。
17. **ECA和P2组合一定最好吗？** 本次test-dev上P2单独模型mAP50–95为17.35%，组合为17.28%；两者差0.07个百分点，单种子不足以证明组合更优。P2相对基线的提升更明确，但需报告速度代价。
18. **漏检可能来自哪里？** 像素信息不足、遮挡、训练分布不足、回归偏移、置信度阈值和NMS抑制；需要逐图核对。
19. **改进没有提高精度怎么办？** 保留真实表格，分析ECA/P2是否适用、是否增加误检或开销；不能更换测试集追求好看的数字。
20. **课程知识如何应用？** 人工智能对应模型学习，模式识别对应特征与分类，概率统计对应评价，程序设计对应模块与异常处理，工程伦理对应隐私与责任边界。
21. **个人做了什么？** 根据实际分工回答；报告中的个人心得与工作贡献须由本人补充，不能照读虚构经历。
